Computer Engineering for Babies — interactive web game concept

A page-by-page logic playground: press buttons, watch wires carry signal, light an LED only when the gate rule is true. Same physical honesty as Chase Roberts’ board book — adapted into paced puzzles for the browser.

Ages ~3–10 + curious adults Core loop: press → signal → rule → light Low-stim by default

High-level concepts

Computers are on/off signals. Gates are rules for combining those signals. The game never “explains programming” abstractly — it lets the player feel the rule through buttons, wires, and a light.

One page = one idea

Each level mirrors a book page: one gate, one LED color, one rule. No side quests on the same screen.

Signal is visible

Wires change state when “hot.” The player sees electricity as a path, not a score popup.

Discovery before labels

Try buttons first. Truth tables and gate names appear after the light behavior is found (parent mode can reverse this).

Compose later

Early levels are atomic gates. Later levels wire gates together (book LATCH = memory from prior symbols).

Joint play

Per Google’s kids guidance: a parent panel with plain-language “why this matters” and real-world examples, gated for adults.

No fail state

Wrong presses just keep the LED off. Soft visual hints after idle time — never red X / timer pressure.

Mid-level puzzles & interactions

Each interaction stays tactile: large buttons, hold or toggle modes, and a single LED win condition. Complexity grows by adding wires and gates — not by adding UI chrome.

Press & Hold Wire

Tutorial

Button depressed = high. LED follows while held. Teaches “signal is momentary unless something remembers it.”

Broken Wire

Interaction

A gap in the trace. Player drags a jumper segment to complete the path (single finger drag — Google kids: no multi-gesture).

Find the Rule

Discovery

Gate symbol is blank. Player experiments until LED matches a hidden truth table; then the symbol fades in.

XOR Door

Puzzle

“Door unlocks only if exactly one switch is on.” Two buttons, one LED lock. Fail = both on / both off (door stays shut, no penalty).

AND Handshake

Co-op

Two players (or two hands) must hold both buttons. Optional: buttons on opposite sides of the screen for joint engagement.

NOT Night-Light

Metaphor

Pressing “day” turns the light off; releasing turns it on. Parent note: motion sensor lights, active-low logic.

Latch Alarm

Memory

SET rings a calm LED “alarm” that stays on after release. RESET clears. Introduces state without words like “flip-flop.”

Build a Latch

Compose

Drag NOT / AND / OR tiles onto a board until SET/RESET behavior matches the target. Same composition idea as the book’s final page.

Half-Adder Spark

Web-only

Two bits in → Sum (XOR) + Carry (AND). Two LEDs. First time the player sees a gate family compute something “math-like.”

Mystery Bus

Sandbox

Free play board: place buttons, gates, LEDs. No goal. Save a “page” to share. Sandbox unlocked after Latch.

Interaction grammar (keep tiny)

  • Tap / hold buttons (primary).
  • Drag one wire segment or one gate tile (secondary).
  • Page turn (prev / next always visible — icons + short labels).
  • Never: pinch, double-tap chains, timed challenges, autoplay audio.

Low-stim UI style

Style is not “cute chaos.” It is calm board-book engineering: soft mint field, quiet PCB texture, high-contrast text, signal colors only when a wire or LED is high. Defaults below follow published low-stim / kids / a11y guidance (sources at bottom) — not vibes.

Palette tokens

Color system rules

  • Neutrals dominate — IBM Carbon / Design Language: gray/mint field carries layout; accent is for action only.
  • Mute saturation — VP0 low-stim: avoid harsh high-sat clashes; signal green is mid, not neon.
  • WCAG AA contrast — ink on page ≥ 4.5:1 (W3C 1.4.3). Large labels ≥ 3:1.
  • Color is never the only cue — W3C 1.4.1 / NDC D3.1: LED also changes shape label (“ON”), wires thicken or get dashes when hot.
  • Role tokens, not raw hex in components — Carbon pattern: --signal, --ink, themes can swap later.

Type & layout

  • Display: Fraunces (soft optical size) for page titles only.
  • UI/body: IBM Plex Sans — readable, technical-adjacent, not a default system stack.
  • Mono: IBM Plex Mono for gate names / truth bits.
  • One focal point — NDC D3.4: board + buttons + LED. Chrome stays thin.
  • Big targets — Google Building for Kids: ≥ 48×48px; prefer ~56–72px circles like the book.
  • Always-visible nav — home / back / next with icon + text.

Motion, sound, sensory control

Do

  • Brief wire/LED state fades (~150–200ms).
  • Honor prefers-reduced-motion (Apple HIG / web.dev): replace slide/zoom with crossfade or instant state.
  • User-started sound only; parent toggle for mute (VP0, NDC D3.3).
  • Sensory settings: motion / sound / contrast (VP0 checklist).
  • Multi-channel feedback: visual + optional soft click + optional haptic (Google kids: don’t rely on one mode).

Don’t

  • Autoplay music, voiceover, or video on page load.
  • Flash / pulse LED faster than ~3Hz; no seizure-risk patterns (W3C).
  • Parallax PCB, spinning gates, particle “level clear.”
  • Score streaks, countdown timers, or angry red error screens.
  • Rearranging nav between pages (VP0: predictability).
